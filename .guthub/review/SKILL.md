# Review Skill

目的
- 在提交和推送前执行统一的代码评审检查，减少缺陷和回归。

使用时机
- 用户要求“review”。
- 用户要求“提交代码”“推送代码”前的质量门禁。
- 进行较大重构、接口变更、依赖升级后。

Review Check 点
1. 需求与范围
   - 改动是否满足需求，是否包含无关改动。
   - 是否有潜在行为变化未在说明中体现。
2. 正确性
   - 核心逻辑是否正确，边界条件和异常路径是否覆盖。
   - 空值、超时、并发、资源释放是否安全。
3. 接口与兼容性
   - 对外接口、配置项、数据结构变更是否兼容。
   - 若不兼容，是否提供迁移说明。
4. 安全性
   - 是否引入明文密钥、敏感信息泄漏风险。
   - 输入校验、注入、权限控制是否合理。
5. 性能与稳定性
   - 是否引入明显性能回退或额外阻塞。
   - 是否存在潜在死循环、内存泄漏、连接泄漏。
6. 可维护性
   - 命名、结构、注释是否清晰。
   - 是否避免过度复杂实现，重复逻辑是否收敛。
7. 测试与验证
   - UT/SCT/集成测试是否覆盖本次改动路径。
   - 本地测试命令与结果是否可复现。
8. 提交质量
   - Commit message 是否符合 Conventional Commits。
   - 提交粒度是否合理，是否便于回滚与追踪。

输出要求
- 先列 Findings（按严重级别排序）。
- 无问题时明确写“未发现阻断问题”，并给出残余风险。
- 若存在阻断问题，不执行 push，先修复或获得明确豁免。
